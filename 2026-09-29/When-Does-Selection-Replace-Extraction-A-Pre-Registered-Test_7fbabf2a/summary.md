# 论文速读：When-Does-Selection-Replace-Extraction-A-Pre-Registered-Test

## 一句话总结
本研究通过预注册非劣效性测试证明：在严格上下文预算下，使用类型化决策模型 Jev 对原始对话轮次进行单次重排序，其性能足以匹敌基于 LLM 提取事实的记忆系统（非劣效性边界 −3.0 点 > −5 点注册边际），且写入成本降低 3,061 倍；同时发现重排序收益随预算增大而显著下降，为现有文献结论分歧提供了统一解释。

## 研究问题与动机
1. **核心问题**：对话记忆是否必须依赖 LLM 提取的结构化事实，还是通过有效选择原始对话轮次即可达到同等效果？
2. **现有方法分歧**：提取派系统（如 mem0、engram）报告提取压缩带来的性能增益；原始历史派（如 SmartSearch、Fidelity Before Structure）则发现原始轮次配合良好排序同样有效，但两派对“重排序是否关键”结论矛盾。
3. **潜在原因假设**：作者认为上下文预算（答案模型实际读取的条目数）是分歧根源——预算紧时（保留少量候选）选择机制至关重要，预算宽松时（保留多数候选）相似度排序已包含大部分证据，重排序收益自然减小。
4. **研究目标**：在预注册框架下，于未见对话数据上严格检验原始轮次+Jev选择器是否非劣效于强提取基线（engram v2），并量化重排序收益随预算变化的趋势。

## 核心贡献（创新点）
1. **首次预注册非劣效性测试**：在严格预算（约265 token/问题）下证明原始轮次选择非劣效于LLM提取记忆（单侧95%边界−3.0点），且写入成本降低3,061倍；本质区别在于采用预注册计划和非劣效性边界，控制了开发数据污染，提供了比单纯准确率报告更严谨的证据。
2. **首次答案级匹配上下文评估类型化决策模型**：证明Jev作为选择器在匹配上下文下性能非劣效于gpt‑4o‑mini列表重排序器（边界−2.0点），且延迟仅为其三分之一；本质区别是将Jev定位为一个高效的一次性选择器，而非仅用于记忆构建。
3. **揭示重排序收益的预算依赖性**：在同一研究内发现重排序增益随预算增大从+17.4点（k=3）降至+1.5点（k=20），解释了SmartSearch与Fidelity Before Structure的结论差异；本质区别是系统性地控制预算变量，而非单一实验设置下的片面结论。
4. **提供细粒度诊断分析**：定位性能瓶颈主要来自短列表遗漏（11.5%的问题）和重排序丢弃（9.2%的问题），尤其是时间证据；本质区别是超越最终准确率，深入分析错误来源，为后续优化指明方向。

## 方法详解
1. **存储表示**：
   - **原始轮次系统**（Turns + Jev / Turns + cosine）：每轮对话保留原文、发言者和日期，以`[date] speaker: text`格式存入向量库。
   - **提取系统**（engram v2）：LLM（gpt‑4o‑mini）逐条提取事实，每个事实附带来源引文和有效期窗口，构成结构化记忆。
2. **选择机制**（Turns + Jev）：
   - 先用余弦相似度生成短列表`C(q) = Top_n(cos(e(q), e(m)))`，`n=30`。
   - 对短列表中每个候选，通过**一次**Jev请求提问相关性（`Q_rel`）：`Does this memory help answer the query?`，Jev返回每个选项的概率。
   - 按概率阈值`τ=0.5`过滤，保留相关轮次按概率降序排列；不足`k`时由余弦底垫（top‑f=10）补充，最终送入答案模型。
3. **类型化决策模型 Jev**：
   - 固定选项集`O_Q`，对状态`s`和问答`Q`返回概率分布`p(o|s,Q)`，决策取最大概率选项，置信度为对应概率；输出无需解析，可直接阈值过滤。
4. **匹配上下文规则**：
   - 比较不同系统时，固定答案模型读取的token数相近：`k* = argmin_k |T_J(k) - T_B(k_B)|`，其中`T_A(k)`为系统A在k条候选时的平均渲染token数。
5. **预注册非劣效性检验 H1**：
   - 假设差值`d_i = c_i^J - c_i^E`（Jev正确记1，否则0），样本均值`d̄`，标准差`s`，样本量`N=778`。
   - 非劣效条件：`d̄ - z_{0.95}·(s/√N) > -δ`，其中`z_{0.95}=1.645`，边际`δ=5`点（基于开发集重排序效应的一半）。
6. **成本度量**：
   - 总成本`C = r_w·c_write + c_read + c_answer`，其中`r_w=4.0`（每问题写入轮次数）；写入成本主要来源于LLM提取调用，读取成本主要为Jev或LLM重排序请求。

## 实验与结果
- **数据集**：
  - **LoCoMo**：五个持话出对话（conv‑44至50），共3,122轮，778个评分问题（多跳140、时间165、开放域50、单跳423）。
  - **LongMemEval**：全量500个用户+助手轮次（470个评分问题，30个弃权问题）。
- **评估基线**：Turns + cosine、Turns + Jev、Turns + LLM、engram v2、mem0 2.1.0、Jev‑Mem、完整上下文。
- **主要结果**：
  - **H1通过**：Turns + Jev（k=6，265 token）对比 engram v2（k=3，251 token），准确率77.0% vs 77.5%，差值−0.5点，单侧95%边界−3.0点 > −5点边际；重排序关闭了相似度与提取之间94%的差距。
  - **预算依赖性**：重排序增益随k增大而下降——LoCoMo上从k=3的+17.4点降至k=20的+1.5点；LongMemEval上从+9.1点降至+1.1点。
  - **类型化模型优势**：Turns + Jev在匹配上下文下非劣效于LLM重排序器（S4，边界−2.0点），且读取延迟约为后者的三分之一；同时显著优于Jev‑Mem（S2，需多次Jev请求图遍历）。
  - **成本对比**：enram v2写入成本$1.865/千轮次，Turns + Jev仅$0.0006/千轮次（仅嵌入），写入成本比达3,061:1。
  - **人类盲评**：严格映射下差值−1.7点，边界−3.9点；宽松映射下差值−2.6点，边界−4.7点，均通过非劣效检验。
  - **性能瓶颈**：短列表遗漏（11.5%问题）、重排序丢弃（9.2%问题），时间证据在重排序阶段丢失最多（22.7%）。
  - **最强结果**：后验扩展版 Turns + Jev (wide) 在k=47（2000 token）下达到81.5%准确率，但未参与注册检验。

## 相关工作脉络
1. **mem0 (Chhikara et al., 2025)**：每轮提取事实并向量检索；本文测试其开源版2.1.0，发现提取在严格预算下并非必要，且本文采用预注册框架提供更严谨对比。
2. **SmartSearch (Derehag et al., 2026)**：主张重排序是关键瓶颈；本文解释其高收益源于极严格预算（平均保留约62段/431候选，比例约14.6%，与本文k=3/30≈10%类似），而宽松预算下收益自然下降。
3. **Fidelity Before Structure (An, 2026)**：发现原始轮次优于提取制品，且重排序边际；本文指出其预算较宽（保留15/30候选），与本文k=20趋势一致，从而统一了两者结论。
4. **Jev‑Mem (Jiang et al., 2026a)**：利用Jev进行多图遍历路由；本文证明单次请求的选择器在匹配上下文下更准确且延迟更低，避免了多轮Jev调用的开销。
5. **Kang et al. (2026)**：研究给定证据后是否合并压缩的预算依赖决策；本文从端到端选择角度提供互补证据，两者一致表明压缩策略强烈依赖上下文预算。
6. **LazyMem (Yu et al., 2026)**：查询时延迟构造记忆，压缩相关片段；本文方法仅在读取时选择原始轮次，不进行重写，在严格预算下达到可比性能，且写入成本更低。

## 局限性与未来方向
- **基准局限**：仅使用LLM生成的LoCoMo和LongMemEval，对话类别较小；未来需拓展至真实用户对话及其他语言。
- **长历史覆盖不足**：LongMemEval未运行engram v2，无法得出提取系统对超长历史的结论；未来应补全对比。
- **人类评分偏差**：评分者为系统构建者，映射规则未预注册；未来需引入第三方盲评。
- **对抗性测试缺失**：未评估提示注入等对抗性输入对选择器的影响；未来需进行鲁棒性分析。
- **闭源模型依赖**：Jev为闭源版本化模型；未来可探索开放同类模型或训练轻量替代品。
- **后验变体**：Turns + Jev (wide) 未在预注册计划中，仅作假设生成；未来需独立验证。
- **绝对准确率**：本文协议下最佳结果低于SmartSearch报告的91.9%，主要因协议和基准不同；未来可在统一协议下比较。
- **开发数据单一**：所有设计选择仅基于一个对话（conv‑26）；未来需在更多开发集上验证泛化性。

## 研究启发与可借鉴点
1. **预注册非劣效性测试框架**：可作为系统比较的新标准，有效控制开发数据污染和选择性报告，提升研究可信度。
2. **匹配上下文评估范式**：通过调整k使各系统读取token数相近，确保公平比较，适用于任何检索‑生成管线。
3. **类型化决策模型作为高效选择器**：一次性概率输出适合低延迟、低成本场景，可替代复杂LLM重排序流程。
4. **预算敏感性分析**：通过系统变化上下文预算揭示方法性能边界，有助于统一文献中看似矛盾的结论。
5. **细粒度诊断指标**：短列表召回、重排序丢弃率等可作为标准评估组件，指导系统优化方向。

## 关键术语表
**Jev**：TypeSafe AI开发的类型化决策模型，对固定选项集返回概率分布，单次请求完成相关性判断，无需解析输出。  
**Turns + Jev**：将对话轮次嵌入存储，通过Jev重排序选择相关轮次供答案模型读取的系统，本文核心提案。  
**engram v2**：作者早期系统，使用LLM提取事实，Jev进行类型化和关系推理，作为本文提取基线。  
**非劣效性测试**：统计检验判断新系统是否不差于基准系统一定边际内的方法，本文使用单侧95%边界。  
**短列表召回**：衡量证据轮次是否出现在初始余弦相似度候选集（top 30）中的比例，用于定位检索瓶颈。  
**上下文预算**：答案模型实际读取的token数量，决定选择机制的重要性；预算越紧，重排序收益越大。  
**类型化决策**：Jev模型通过固定选项和概率输出进行确定性选择的过程，区别于自由生成。  
**预注册**：在实验前公开研究计划和分析方法，以减少偏差并增强结果可信度的实践。

## 可复现要素
- **数据集**：LoCoMo（conv‑44至50持话出子集）、LongMemEval cleaned；均为公开基准。
- **代码/权重**：代码、计划、答案和人类评分已开源于 github.com/ris3abh/Engram（tags v3‑frozen, v3‑amended）；无自定义模型权重。
- **关键超参**：短列表大小`n=30`，相关性阈值`τ=0.5`，Jev模型版本`jev‑1.13.0`，回答模型`gpt‑4o‑mini`（temperature=0），嵌入模型`textembedding‑3‑small`；非劣效性边际`δ=5`点；匹配上下文规则见 Eq. (5)。
